# kr3-responsive-shop

## Контрольная работа №3

Тема: «Адаптивная вёрстка и доступность многостраничного HTML/CSS-сайта».

## Описание

Учебный интернет-магазин ShopProject. Основа проекта перенесена из контрольной работы №1
(HTML/CSS без фреймворков) и будет адаптирована под разные размеры экранов.

## Структура проекта

- `index.html` — главная страница: hero-блок, преимущества, популярные товары;
- `catalog.html` — каталог с фильтром;
- `product.html` — карточка товара и таблица характеристик;
- `order.html` — форма заявки;
- `contacts.html` — контакты и форма обратной связи;
- `css/style.css` — базовые стили проекта;
- `css/responsive.css` — адаптивные стили (Mobile First);
- `js/main.js` — бургер-меню и открытие/закрытие модального окна;
- `images/` — изображения;
- `lighthouse/` — отчёты Lighthouse (Accessibility);
- `README.md` — описание проекта.

## Адаптивные решения

- Добавлен файл `css/responsive.css`, подключён на всех страницах после `style.css`,
  чтобы адаптивные правила переопределяли базовые.
- На всех страницах есть `meta viewport`.
- Применён подход **Mobile First**: базовые стили написаны для мобильного экрана,
  расширения для больших экранов добавляются медиазапросами `min-width`.
- Из `style.css` убраны фиксированные колонки сеток (`grid-template-columns`),
  раскладка задаётся в `responsive.css`.
- Для изображений и видео задано `max-width: 100%` и `height: auto`.
- Для всех элементов задано `box-sizing: border-box`.
- Отступы контейнеров (`main`, шапка, подвал): 16px на мобильном, 24px с 768px.
  Края шапки, содержимого и подвала совпадают.

### Навигация

- На мобильном экране меню скрыто за бургер-кнопкой. Логотип и кнопка стоят в одной
  строке, меню раскрывается под ними столбиком (`flex-wrap: wrap` + `flex-basis: 100%`).
- Пункты меню занимают всю ширину и имеют высоту не меньше 44px, чтобы их было
  удобно нажимать пальцем.
- С 768px бургер скрыт, меню выводится в строку (`flex-direction: row`, `flex-wrap: wrap`).
- Шапка закрепляется при прокрутке (`position: sticky`) только с 768px.
  На мобильном она обычная, чтобы не закрывать содержимое экрана.

### Hero-блок

- На мобильном экране hero-блок в одну колонку: текст, под ним изображение.
- С 900px две колонки: `grid-template-columns: minmax(0, 1fr) minmax(280px, 420px)`.
  Брейкпоинт выбран по содержимому: на 768px двум колонкам тесно.
- Размер заголовка задан через `clamp(28px, 7vw, 48px)`: шрифт плавно растёт
  вместе с шириной экрана, но не меньше 28px и не больше 48px.
- Кнопки переносятся на новую строку, если не помещаются (`flex-wrap: wrap`).
- Длинные слова в заголовке переносятся (`overflow-wrap: break-word`).
- В hero-блоке используется `<picture>` с разными кадрами (art direction):
  квадратный на мобильном, широкий с 640px, вертикальный с 900px,
  когда hero перестраивается в две колонки.
- Для каждого кадра есть версия в формате WebP (`type="image/webp"`),
  она на 40% легче JPEG. Браузеры без поддержки WebP получают JPEG.

### Сетки карточек

- Сетка товаров (`.products-grid`) и блок преимуществ (`.advantages`) построены на CSS Grid:
  1 колонка на мобильном, 2 колонки с 640px, 3 колонки с 1024px.
- Колонки задаются через `repeat(N, minmax(0, 1fr))`, чтобы длинное содержимое
  не растягивало колонку и не вызывало горизонтальный скролл.
- У карточек `min-width: 0`, у названия и описания `overflow-wrap: anywhere`:
  длинные слова переносятся и не ломают карточку.
- Кнопки «Подробнее» и «Заказать» переносятся на новую строку в узких карточках
  (`flex-wrap: wrap`).

### Изображения карточек

- Изображения товаров имеют одинаковые пропорции `aspect-ratio: 1 / 1`
  и `object-fit: cover`: фото разных размеров заполняют рамку без искажений,
  карточки в ряду одной высоты.
- У изображений в HTML указаны `width` и `height`, чтобы браузер заранее
  резервировал место и страница не «прыгала» при загрузке.
- Для изображения первого товара используются `srcset` (файлы 480w, 640w, 960w)
  и `sizes`, повторяющий сетку: 100vw до 640px, 50vw до 1024px, 33vw дальше.
  Браузер сам выбирает подходящий файл. Изображения ниже первого экрана
  загружаются лениво (`loading="lazy"`).

### Каталог и фильтр

- На мобильном экране каталог в одну колонку, фильтр расположен над товарами (`order: -1`).
- С 1024px две колонки: `grid-template-columns: 280px minmax(0, 1fr)`.
- Фильтр закрепляется при прокрутке (`position: sticky`) только с 1024px,
  с отступом `top: 88px`, чтобы не заезжать под закреплённую шапку.
  На мобильном sticky отключён, чтобы высокий фильтр не закрывал товары.
- Внутри каталога сетка товаров: 2 колонки с 1024px и 3 колонки с 1280px,
  так как рядом с фильтром места меньше, чем на главной.
- На экранах до 1024px форма фильтра свёрнута и открывается кнопкой «Показать фильтры».

### Страница товара и таблица

- На мобильном изображение товара и описание идут друг под другом,
  с 768px в две колонки.
- Таблица характеристик обёрнута в `.table-wrapper` с `overflow-x: auto`:
  на узком экране прокручивается только таблица, а не вся страница.
  У таблицы `min-width: 480px`, чтобы ячейки не сжимались.
- На экранах до 640px таблица характеристик выводится как набор карточек
  «параметр — значение» (`display: block` у строк и ячеек), без горизонтальной
  прокрутки. Заголовок таблицы визуально скрыт, но остаётся доступным
  для скринридеров. Для этого вида использован `max-width`, чтобы не
  восстанавливать табличные свойства на больших экранах.

### Формы

- На мобильном экране формы заявки и обратной связи идут в одну колонку,
  с 768px форма заявки в две колонки (комментарий, согласие и кнопки на всю ширину).
- Поля имеют высоту не меньше 44px и шрифт 16px: удобно нажимать пальцем,
  и Safari на iPhone не увеличивает масштаб при фокусе на поле.
- Чекбокс согласия увеличен до 20×20px.
- Кнопки формы переносятся на новую строку на узких экранах (`flex-wrap: wrap`).
- Форма в модальном окне всегда в одну колонку: селектор `.order-dialog .order-form`
  специфичнее, чем правило из медиазапроса.

### Контакты

- На мобильном контактная информация и форма обратной связи идут друг под другом,
  с 768px в две колонки.

### Модальное окно и фиксированные элементы

- Ширина модального окна `min(100% - 32px, 560px)`, высота не больше экрана,
  при нехватке места внутри окна появляется прокрутка.
- Кнопка «Наверх» на мобильном ближе к углу экрана (16px) и не перекрывает
  содержимое, высота не меньше 44px.
- При переходе по якорям заголовки разделов не прячутся под закреплённой
  шапкой (`scroll-margin-top`).

### Подвал

- На мобильном экране текст и ссылки подвала идут друг под другом,
  ссылки переносятся на новую строку (`flex-wrap: wrap`). С 768px — в одну строку.

## Доступность

- Бургер-меню сделано на элементе `<button type="button">`, поэтому работает
  с клавиатуры (Tab, Enter, пробел).
- У кнопки есть `aria-label` («Открыть меню» / «Закрыть меню»), `aria-controls`
  со ссылкой на список меню и `aria-expanded`, который JavaScript меняет
  на `true`/`false` при открытии и закрытии.
- Полоски иконки скрыты от скринридеров через `aria-hidden="true"`.
- У бургер-кнопки есть видимый фокус (`:focus-visible`).
- Кнопка сворачивания фильтра — элемент `<button type="button">` с видимым текстом,
  `aria-controls` (ссылка на форму фильтра) и `aria-expanded`, который меняется
  при открытии и закрытии.
- У заголовков таблицы указан `scope` (`col` для столбцов, `row` для строк).
- Прокручиваемая область таблицы доступна с клавиатуры: `tabindex="0"`,
  `role="region"` и `aria-label`, видимый фокус.
- Добавлена ссылка пропуска к основному содержимому (skip-link): появляется
  при первом нажатии Tab, скрыта визуально (сдвигом за край экрана),
  а не через `display: none`, чтобы оставаться доступной с клавиатуры.
- Текущая страница отмечена `aria-current="page"` в меню и хлебных крошках.
- Видимый фокус `:focus-visible` на всех интерактивных элементах: общее правило
  для всего сайта и отдельные стили для меню, кнопок и полей. На активном
  пункте меню рамка фокуса белая, чтобы быть видной на синем фоне.
  Нигде не используется `outline: none`.
- Проверена структура заголовков: один `h1` на странице, порядок `h1 → h2 → h3`.
- Ссылки используются для переходов, кнопки — для действий (`<div onclick>` не используется).
- У изображений осмысленные `alt` на русском языке.
- У всех полей форм есть `label`, обязательные поля отмечены звёздочкой,
  в том числе в модальном окне.
- Модальное окно реализовано на `<dialog>` с `showModal()`: фокус переходит
  внутрь окна, Esc закрывает его, содержимое страницы за окном недоступно.
  Окно подписано заголовком через `aria-labelledby`.
- Проверен контраст всех цветовых пар: минимальный 5.2 : 1 (серый текст
  на светлом фоне), что выше требования WCAG AA (4.5 : 1).
- Сайт полностью проверен с клавиатуры (Tab, Shift+Tab, Enter, пробел, Esc)
  на всех пяти страницах.

## Проверенные ширины

Проект проверен в DevTools на ширинах 360px, 430px, 768px, 1024px и 1440px
на всех пяти страницах. Горизонтального скролла страницы нет: прокручивается
только таблица характеристик внутри своего контейнера.

## Lighthouse

Проверка выполнена в Chrome DevTools → Lighthouse, режим Navigation,
устройство Mobile, категория Accessibility, в окне инкогнито.

| Страница | Accessibility |
|---|---|
| `index.html` | 100 |
| `catalog.html` | 100 |
| `order.html` | 100 |

Отчёты сохранены в папке `lighthouse/`.

Lighthouse проверяет только то, что можно найти автоматически, поэтому
дополнительно выполнена ручная проверка с клавиатуры и проверка контраста.

## Самостоятельные доработки

- **Бургер-меню для мобильных экранов.** Меню открывается и закрывается кнопкой,
  иконка анимированно превращается из ☰ в ✕ через селектор по атрибуту
  `[aria-expanded="true"]`. Логика в `js/main.js`: переключение класса `is-open`
  через `classList.toggle()` и обновление `aria-expanded`.
- **Сворачиваемый фильтр каталога.** На мобильном экране форма фильтра скрыта
  и открывается кнопкой, текст кнопки меняется на «Скрыть фильтры».
  С 1024px кнопка скрыта, фильтр всегда открыт и закреплён при прокрутке.
  Логика в `js/main.js`: класс `is-open` и атрибут `aria-expanded`.
- **WebP-изображения через `<picture>`** с запасным JPEG для старых браузеров.
- **Карточное представление таблицы на мобильном** вместо горизонтальной прокрутки.
